# 라벨링 가이드 (custom_data)

라벨러가 판단으로 갈릴 수 있는 지점을 **미리 규칙으로 고정**해 둔 문서다.
규칙이 없으면 30장짜리 셋에서도 라벨러별로 5~6장이 갈리고, 그만큼이 그대로
"모델 오류"로 잘못 집계된다.

---

## 0. 작업 순서

1. `prepare_images.py`가 만든 `labels.csv` 뼈대에는 `image_id`만 채워져 있다.
2. **두 명이 서로 안 보고 독립 라벨링** → 불일치 건만 모아 합의(adjudication).
   - 30장 기준 30분 이내. 불일치 건수와 합의 결과는 `notes`에 남긴다.
   - 이 절차 자체가 요약서에 쓸 "라벨 신뢰성 근거"가 된다 (불일치율 보고).
3. `validate_labels.py`로 형식 검증 → 통과해야 커밋.

---

## 1. 무엇을 정답으로 보는가 (핵심 규칙)

### P1. 정답은 "소비기한류 키워드가 가리키는 날짜" 하나다
| 정답으로 본다 | 정답으로 보지 않는다 |
|---|---|
| 소비기한 / 유통기한 / 사용기한 / 품질유지기한 | 제조일자 · 제조연월 · MFG · PKG(포장일) |
| EXP / EXP.DATE / Use by / Best before / BB | LOT · 제조번호 · 품목보고번호 · 바코드 숫자 |
| 賞味期限 / 消費期限 / 使用期限 | 시각(14:32) · 공장코드 · 가격 |

> 가장 늦은 날짜가 정답이라는 규칙은 쓰지 않는다. **키워드가 우선**이고,
> 키워드가 아예 없을 때만 보조 규칙(P4)으로 내려간다.

### P2. 연-월만 인쇄된 경우 (의약품·화장품에서 매우 흔함)
`EXP 2026.09`처럼 일(day)이 인쇄되지 않았으면 **날짜를 만들어내지 않는다.**

```
year=2026, month=09, day=NONE, final_date=2026-09-NONE, tag_ymonly=TRUE
```

말일(30일)이나 1일로 채우지 말 것. 채점이 연·월·일 **항목별 부분점수**이므로
비워도 연·월 점수는 그대로 들어오고, 잘못 채우면 일(day) 항목만 확정 0점이 된다.

### P3. 상대 표기 (제조일로부터 N개월 / 개봉 후 사용기간)
| 상황 | 라벨 |
|---|---|
| 제조일자 + "제조일로부터 24개월"이 **둘 다** 보인다 | 계산한 날짜를 정답으로. `tag_relative=TRUE`, `notes`에 계산식 |
| "개봉 후 12개월(12M)" 만 있다 | 개봉일은 알 수 없음 → 이 문구는 무시. 다른 표기가 없으면 `NONE` |
| 기준일 없이 "제조일로부터 2년"만 있다 | `NONE`, `tag_relative=TRUE` |

> 화장품 PAO 심볼(열린 용기 그림 + `12M`)은 **소비기한이 아니다.** 절대 정답으로 쓰지 않는다.
> 우리 파서의 `RELATIVE_EXPR_AS_NONE` 정책 스위치와 비교할 때
> "정책을 켜고 끈 차이"를 재려면 이 태그가 반드시 필요하다.

### P4. 키워드가 없고 날짜만 여러 개인 경우
1. 날짜 형태가 하나뿐 → 그것을 정답으로, `notes`에 "키워드 없음" 기록.
2. 둘 이상이고 판단 근거가 없다 → **가장 늦은 날짜**를 정답으로 하되
   `tag_multidate=TRUE`, `notes`에 "근거 약함" 기록. 이 건들은 오류 분석에서 따로 뺀다.

### P5. "상단 표기일 참조" 류
포장에 날짜가 아니라 위치만 적혀 있고, 실제 날짜가 사진에 **보이면** 그 날짜가 정답.
사진에 안 보이면 `NONE` + `tag_reference=TRUE`.

### P6. 사람 눈으로도 못 읽는 경우 — "미표기"와 "판독 불가"를 구분한다
| 상황 | status | 값 |
|---|---|---|
| 표기가 있는데 흐림·반사로 판독 불가 | `완료` | `NONE` + `tag_unreadable=TRUE` |
| 확대해도 끝내 확신이 안 선다 (라벨러 2명 모두) | `보류` | 채점 제외 |
| 애초에 소비기한 표기가 없는 제품 | `완료` | `NONE` (태그 없음) |

`보류`는 `evaluate.py`가 자동으로 제외한다. 남발하면 셋이 쉬워지므로 최대 2장까지.

### P7. 2자리 연도 · 수입품 순서
- `26.09.11` → 2026년. 2자리 연도는 20xx로 확장한다.
- `11.09.26`처럼 **DD.MM.YY 가능성**이 있으면 제품 원산지·다른 표기(제조일)와 대조해 판정하고,
  판정 근거를 `notes`에 남긴다. 원문은 무조건 `notation_raw`에 그대로 적는다.

### P8. 일본 제품 — 용어별 처리 (팀 정책)
| 표기 | 뜻 | 라벨 정책 |
|---|---|---|
| `消費期限` | 소비기한 (안전 한계) | 정답으로 라벨, `term=消費期限` |
| `賞味期限` | 품질유지기한 (맛 보증) | **정답으로 라벨하되** `term=賞味期限` 으로 구분 기록 |
| `使用期限` | 사용기한 (의약품·화장품) | 정답으로 라벨, `term=使用期限` |

> `賞味期限`은 엄밀히는 우리 과제의 소비기한과 다르다. 그래도 정답으로 잡는 이유는,
> 대회 채점이 "포장에 표기된 기한 날짜"를 묻기 때문이다. `term` 컬럼으로 분리해 두면
> 나중에 정책을 바꿔도 재라벨링 없이 `term`으로 걸러 다시 계산할 수 있다.
> 연호 표기(`令和8年` = 2026년)가 나오면 서기로 환산하고 `notes`에 원표기를 남긴다.

## 2. 제품군별 자주 나오는 함정

| 제품군 | 함정 | 대응 |
|---|---|---|
| 영양제·건기식 | 용어가 아직 "유통기한"인 제품이 많음. 병뚜껑 **각인**이라 저대비 | `tag_engrave`, `tag_lowcontrast` |
| 의약품 | **연-월만** 표기가 기본. `Lot No.`가 날짜 바로 옆 | `tag_ymonly`, `tag_lotconfuse` |
| 화장품 | 제조일자만 인쇄 + "제조일로부터 N개월" 별도 문구. PAO 심볼 혼동 | `tag_relative`, P3 |
| 일본 수입품 | 한자 키워드 + 수입사 스티커의 한글 표기가 **둘 다** 있고 날짜가 다를 수 있음 | 한글 스티커가 덮은 경우 스티커 쪽이 정답, `notes` 기록 |
| 공통 | 파우치·튜브의 **곡면**, 투명 포장 뒤 배경 글자 | `tag_curved` |

## 3. 태그 기준 (애매하면 FALSE)

| 태그 | TRUE 조건 |
|---|---|
| `tag_dot` | 잉크젯 도트 매트릭스 — 글자가 점으로 끊겨 보임 |
| `tag_engrave` | 레이저 각인 · 엠보싱 · 음각 (잉크 없음) |
| `tag_curved` | 캔·병·튜브 곡면으로 글자 줄이 휘어 있음 |
| `tag_lowcontrast` | 어두운 바탕의 어두운 잉크, 반사광으로 획이 날아감 |
| `tag_multidate` | 한 화면에 날짜꼴 숫자가 2개 이상 |
| `tag_lotconfuse` | LOT·제조번호·품목보고번호가 날짜와 같은 줄/인접 |
| `tag_relative` | 상대 기간 문구 존재 (계산 성공 여부와 무관) |
| `tag_reference` | "상단 표기일 참조" 류 위치 지시 문구 |
| `tag_ymonly` | 일(day)이 인쇄되어 있지 않음 |
| `tag_foreign` | 한글 외 언어로 기한 키워드가 표기됨 |
| `tag_unreadable` | 표기는 있으나 판독 불가 |

한 이미지에 여러 태그가 붙어도 된다. `evaluate.py`는 태그별 정확도를
각각 집계하고, 태그가 하나도 없는 건은 "평이"로 묶어 보여준다.

## 4. parser_cases.csv (이미지 없이 도는 회귀 테스트)

`notation_raw`에 적은 원문 표기를 그대로 옮겨 **날짜 파서만** 단독 검증하는 표다.
OCR이 완벽했다고 가정했을 때 파서가 맞히는지를 재기 때문에,
오류가 **인식 문제인지 파싱 문제인지**를 분리해 준다 (오류 원인 분해에 그대로 쓰임).

- `case_id` : `pc_001`
- `image_id` : 출처 이미지 (직접 만든 변형 케이스면 비워 둠)
- `input_text` : 파서에 넣을 텍스트 (OCR 출력 대신)
- `expect_year` / `expect_month` / `expect_day` / `expect_final_date`
- `note` : 이 케이스가 노리는 것 (예: "使用期限 한자 키워드 인식")

이미지 1장이 케이스 여러 개를 낳아도 된다(원문 그대로 / OCR 오독 재현 / 구분자 누락 등).
