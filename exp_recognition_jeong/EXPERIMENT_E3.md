# 실험 E3: 인식 단계 전처리 비교 (담당: 정창민)

## 무엇을 재는 실험인가

파이프라인에서 **크롭 이후 ~ 파서 이전 구간만** 떼어내 비교합니다.

```
고정: YOLO 크롭(yolo_scan.csv 박스) → [ 여기가 변수: 전처리 ] → RapidOCR → date_parser.py → 채점
```

검출기와 파서를 고정하니, 점수 차이는 전적으로 전처리에서 온 것입니다. 팀원(KGW)이 "보정 2단 구조로 +3.86%p"를 얻은 지점을 **여러 전처리 중 무엇이, 어떤 사진에서 효과가 있는지**로 분해하는 셈입니다.

## 왜 이 축인가 (제약과의 연결)

- 팀원 측정에서 장당 0.599초 → 500장 기준 299초. 제한 2400초의 **12.5%만 쓰고 있습니다.** 전처리를 몇 개 더 얹을 시간 여유가 충분합니다.
- 같은 측정에서 해상도 상승은 +1.26%p, 파서 수정은 +0.37%p인데 보정은 +3.86%p였습니다. 남은 실패의 성격이 "못 읽는 사진"이라는 뜻이고, 그렇다면 전처리가 지렛대입니다.
- 크롭은 작아서 변형 하나당 비용이 쌉니다. 297장 × 13변형이 수십 분 안에 끝납니다.

## 변형 목록 (`variants.py`)

| 이름 | 내용 | 노리는 난제 |
|---|---|---|
| `none` | 원본 (기준선) | – |
| `up2` | 2배 확대 (Lanczos) | 작은 글자 |
| `clahe` | 국소 대비 강화 | 저대비 |
| `illum` | 흐린 배경으로 나눠 조명·반사 정규화 | 반사광, 밝기 기울기 |
| `sharpen` | 언샤프 마스크 | 초점 불량 |
| `otsu` / `adaptive` | 전역 / 국소 이진화 | 저대비, 배경 무늬 |
| `dotclose` | 확대 → 이진화 → 끊긴 점 잇기 | **잉크젯 도트** |
| `dotclose_auto` | 도트 크기를 추정해 커널 크기 자동 결정 | 도트 간격이 제각각인 경우 |
| `deskew` | 글자 기울기 추정 후 회전 | 기울어진 촬영 |
| `combo_dot` | deskew + dotclose | 도트 + 기울어짐 |
| `combo_lowcontrast` | clahe + illum + sharpen | 어두운 바탕 |
| `combo_all` | deskew + 확대 + clahe + sharpen | 복합 |

## 지표

| 지표 | 정의 | 왜 보는가 |
|---|---|---|
| 부분점수 | year/month/day 각 1/3점 | 운영진 채점 방식(가정) |
| 완전일치 | 세 항목 모두 | 보조 |
| **인식적중** | 정답 날짜의 숫자열이 OCR 텍스트에 있는지 | **파서를 뺀 인식 단계만의 성능.** 파서가 못 살린 것과 인식이 못 읽은 것을 구분 |
| 응답률 | NONE 이 아닌 답을 낸 비율 | 부분점수 체계에서 NONE 은 0점 |
| 장당 시간 | 전처리 + 인식 | 예산 확인 |

## 판정 방법 (중요)

변형끼리 2~3%p 차이는 눈으로 보면 "좋아졌다" 같지만, 297장에서는 우연일 수 있습니다. 같은 이미지에 두 변형을 돌린 **대응표본(paired)** 이므로 McNemar 검정을 씁니다.

- `개선/악화` = 기준선이 틀렸는데 맞힌 장수 / 맞았는데 틀린 장수
- 예: 20/7 이면 p ≈ 0.019 → 유의, 19/8 이면 p ≈ 0.052 → 경계
- 부분점수 차이는 부트스트랩 95% 신뢰구간을 함께 봅니다

`analyze_sweep.py`가 이걸 자동으로 계산합니다. 팀원이 "27장 차이라 못 잰다"고 한 상황도 이 방법이면 판정이 가능합니다.

## 실행 순서

```bash
cd ~/Desktop/상품사진입니다/_itda_work
bash setup_rapid.sh                 # 1회. torch 없이 설치되어 가볍고 빠름
conda activate itda

# 1) 변형이 실제로 어떻게 보이는지 눈으로 확인
python preview_variants.py --n 6 --out preview.jpg

# 2) 빠른 확인: 3개 변형 × 20장 (몇 분)
python sweep_ocr.py --split dev --variants none,dotclose,combo_dot --limit 20
python analyze_sweep.py

# 3) 본 실험: 전체 변형 × dev 297장
python sweep_ocr.py --split dev
python analyze_sweep.py --errors none__m15

# 4) 크롭 여백 실험 (Tier 3-1: "까지" 같은 키워드가 잘리는 문제)
python sweep_ocr.py --split dev --variants none --margin 0.30
python analyze_sweep.py
```

## 결과를 어떻게 쓰나

1. **범주별 표**를 봅니다. `5b_판독불가_EXP각인추정`에서만 `dotclose`가 이긴다면, 전체에 거는 대신 **조건부 라우팅**(도트로 판정된 크롭에만 적용)이 정답입니다. 이게 Tier 2-1이고, 발표에서 설명하기도 좋습니다.
2. **인식적중은 올랐는데 부분점수가 안 올랐다면** 병목은 파서입니다. 반대면 인식입니다. 개선 담당을 나눌 근거가 됩니다.
3. **무응답 중 정답이 NONE인 장수**를 셉니다(자동 출력). 그만큼은 애초에 개선 여지가 아니라 상한선입니다.

## 주의

- holdout 102장은 이 실험에서 절대 열지 않습니다. 변형을 13개나 비교하면 dev에 과적합되기 쉬워서, 최종 선택 후 딱 한 번만 확인합니다.
- 우리 YOLO(EXP/MFG 2클래스)와 팀원 YOLO(4클래스)는 다른 모델입니다. 여기서 나온 전처리 효과를 팀원 파이프라인에 옮길 때는 재측정이 필요합니다.
- 이 실험의 절대 점수는 팀원 숫자(75.72%)와 직접 비교하면 안 됩니다. 검출기·인식 모델·크롭이 다릅니다. **기준선 대비 상대 개선폭**만 옮겨 쓸 수 있습니다.
